Why it exists

Port the crop.
Respect the map.

Custom-crop conversion is not just copying XML and textures. Different maps can use different registry layouts, density references, height-type structures and shared crop-family assets. Crop Porter is being built around those structural differences rather than hard-coded map names.

Inspect

Understand both maps

Probe source and target structures before deciding what can be reused, supplemented or transformed.

Plan

Build a deterministic patch plan

Analyse registries, crop families, asset collisions, I3D IDs and density layouts before any mutation is allowed.

Apply

Change only what is safe

Generate into a separate output, preserve backups and refuse ambiguous structural changes rather than forcing a result.

Portability rule

Map structures.
Not map names.

The engine is designed to detect structural facts such as inline or separate registries, GDM/GRLE versus PNG density references, channel capacity, local height-type registries, terrain-detail-height bit layouts, shared crop-family assets and runtime dependency graphs.

Castlereagh and Hobo's Hollow are validation references, not a whitelist. The goal is to support any target map whose structure falls within the detected FS25 model and to return explicit diagnostics when it does not.

Architectural ruleCompatibility logic must be structural.

No target-map name checks. No fixed I3D ID assumptions. No silent mutation when the target architecture is ambiguous.
